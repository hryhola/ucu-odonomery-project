## Наскільки вдало обрані основні джерела

**Hartley — найпряміше першоджерело для вашого експерименту з нормалізацією.** Саме воно обґрунтовує, чому простий eight-point estimator не слід відкидати через погану чисельну поведінку ненормалізованої системи. Його основний предмет — фундаментальна матриця F та некалібровані зображення; це не повний підручник із fisheye odometry чи відновлення траєкторії. Експерименти статті також не доводять перевагу eight-point над сучасним five-point baseline на UZH-FPV.

**Hartley–Zisserman — найцінніше джерело для математичного ядра саме цього проєкту.** Воно зв'язує епіполярну геометрію, F/E, SVD, чотири можливі пози, тріангуляцію та виродження. Вік книги не є причиною заміни: базова геометрія залишається потрібною. Обмеження — це великий довідник, а не готовий рецепт для сучасного API чи конкретного датасету. Читати всю книгу не потрібно. Перевіряти формули можна також за [errata другого видання](https://www.robots.ox.ac.uk/~vgg/hzbook/hzbook2/HZerrors3.pdf).

**Delmerico et al. — правильне джерело про походження та складність UZH-FPV.** Воно не замінює джерело алгоритму й не є достатньою інструкцією для нинішнього набору даних. На [сайті датасету](https://fpv.ifi.uzh.ch/) зазначено оновлення ground truth у 2022 році та додавання SplitS у 2023 році. Отже, 31 послідовність у `our-case.md` слід розуміти як початковий набір, а не весь актуальний каталог. Вибирати послідовності треба за [поточною таблицею](https://fpv.ifi.uzh.ch/datasets/) і наявністю публічного GT.

## Що додати, не роздуваючи бібліографію

1. **Обов'язково: офіційні UZH-FPV dataset files, калібровка та [супровідний репозиторій](https://github.com/uzh-rpg/uzh_fpv_open).** Потрібні для вибору камери, часових міток, перетворень систем координат і перевірки GT. Сайт окремо просить цитувати роботу Cioffi et al. 2022 про спосіб отримання ground truth; це цільове доповнення при використанні відповідного GT, а не вимога реалізувати їхній SLAM.
2. **Обов'язково: [OpenCV calib3d](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).** Читати `findEssentialMat`, `recoverPose`, `findFundamentalMat` і документацію fisheye. Зафіксувати версію OpenCV, метод, thresholds, confidence і max iterations у відтворюваних експериментах.
3. **Для обґрунтування baseline: D. Nistér, “An Efficient Solution to the Five-Point Relative Pose Problem”, TPAMI 26(6), 756–770, 2004, [DOI](https://doi.org/10.1109/TPAMI.2004.17).** Це доповнення, а не заміна Hartley. Повний текст цієї роботи в межах аудиту не прочитано; рекомендація стосується релевантності до заявленого baseline. OpenCV прямо документує five-point solver у `findEssentialMat`. Не потрібно реалізовувати поліноміальне ядро цього методу для вашого погодженого scope.
4. **Умовно: [EuRoC](https://projects.asl.ethz.ch/datasets/euroc-mav/).** Додавати публікацію Burri et al. 2016, якщо команда справді обере цей датасет для простішого експерименту. Наявність stereo/IMU не зобов'язує використовувати їх: для збереження монокулярного scope можна взяти одну камеру.

Для першого звіту з вимогою 3–5 прочитаних джерел практичне ядро: Hartley, HZ, Delmerico, документація OpenCV і одна робота за фактичною потребою (baseline або використаний GT). Не представляти цей AI-аудит як доказ того, що команда вже прочитала всі джерела.

## Нюанси, які впливають на правильність вашого кейсу

### 1. Розділ про тріангуляцію вже є, але його немає у списку читання

До переліку HZ в `our-case.md` варто додати §12.2 (друковані с. 312–313). Він прямо відповідає вимозі викладача: побудувати однорідну систему для 3D-точки та розв'язати її SVD. §9.6 (257–259) пояснює чотири розклади E та вибір фізично допустимого через додатну глибину. Для шумних даних перевіряти кілька inliers, а не покладатися на одну довільну точку.

### 2. Не змішувати три операції над координатами

- Undistortion компенсує модель лінзи.
- Перехід через K до каліброваних координат потрібен для E.
- Hartley normalisation центрує й масштабує точки для чисельного оцінювання.

Це різні операції. Для експерименту викладача з F брати undistorted pixel coordinates, порівнювати A до/після Hartley normalisation, повертати F у початкові координати і вже потім переходити до E = K₂ᵀ F K₁. Rank-2 constraint для F не вимагає рівності двох ненульових singular values; constraint для E вимагає. Якщо додаткову Hartley normalisation застосовують до каліброваних координат, essential constraint потрібно накладати у фізичних каліброваних координатах після повернення з додаткової нормалізації.

### 3. Fisheye — підтверджений факт для перевіреної конфігурації

В [архіві Indoor forward / Snapdragon](https://download.ifi.uzh.ch/rpg/web/datasets/uzh-fpv/calib/indoor_forward_calib_snapdragon.zip) YAML містить `camera_model: pinhole`, `distortion_model: equidistant`, resolution 640×480. Тобто слова `pinhole` недостатньо, щоб вибрати звичайну radial-tangential correction. Потрібна сумісна з equidistant модель undistortion. Для інших сенсорів/орієнтацій брати саме їхній calibration archive; не переносити ці параметри автоматично.

### 4. Незалежні пари кадрів не дають траєкторію з одним невідомим масштабом

OpenCV документує, що recovered t має одиничну довжину й визначає лише напрям. Математичний наслідок для вашої постановки: для кожної незалежної пари невідомий свій множник αᵢ. Сума одиничних кроків не відновлює реальні відносні довжини переміщень; одного глобального масштабування недостатньо. Основний результат варто формулювати як pairwise R і напрям t. Траєкторію залишити ілюстрацією з явним припущенням про scale або окремою задачею узгодження scale між кадрами. Якщо масштаб береться з GT, це oracle-scale visualization, а не оцінений камерою масштаб.

### 5. cond(A) та spectral gap потребують обережної інтерпретації

Це висновок із структури вашої однорідної системи, а не отриманий експериментальний результат. Для N≥9 і точних невироджених даних rank(A)=8, тому найменше сингулярне число нульове і звичайний cond(A) нескінченний. Це очікуваний nullspace, не автоматична помилка. Аналізувати спектр, відокремлення шуканого null direction, шум і pose error разом; фіксувати визначення кожної метрики.

Для мінімальної вибірки 8×9 існує правий nullspace, але стандартний список singular values має лише 8 елементів. Reduced SVD може не повернути дев'ятий правий вектор. Не можна без пояснення трактувати два останні повернуті числа як σ₈ та σ₉ повної дев'ятивимірної задачі. Площинні точки вироджують лінійне оцінювання F, але це не означає неможливість будь-якого calibrated pose method для площини. Spectral gap — досліджуваний індикатор, а не універсальний детектор усіх збоїв. При чистому обертанні напрям переносу не визначений; при дуже малій базі він нестійкий.

### 6. Baseline має розрізняти перевірку коду й порівняння методів

Власний normalized eight-point проти `findFundamentalMat(..., FM_8POINT)` на тих самих точках перевіряє реалізацію F. Власний eight-point + RANSAC проти five-point + RANSAC порівнює вже різні estimators. Треба узгодити correspondences, систему координат, одиниці порога, confidence та облік невдач. Однакова кількість ітерацій не означає однакової ймовірності успіху для вибірок із 8 і 5 точок.

Для UZH-FPV GT також потрібні timestamps, sensor/body-to-camera extrinsics і правильний напрям відносного transform. Leica position measurements самі по собі не є незалежним виміром повної орієнтації. Використовувати опис саме опублікованого pose GT, а не називати всі його компоненти «прямо виміряними лазером».
